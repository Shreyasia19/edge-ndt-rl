How this maps to the repo: the 8-node star topology mirrors network_emulation/topology.py. Node capacity/bandwidth are drawn from the same Gaussian distributions used for the project's training data (Alibaba Cluster Trace v2018‑derived). This tab is a live, illustrative re-simulation running entirely in JS — it is not a forward pass of digital_twin/model.py's trained GNN. For actual measured fidelity numbers, use the "Python-verified metrics" tab, which reads the output of edge_ndt_digital_twin_sim.py.

Run python edge_ndt_digital_twin_sim.py to regenerate outputs/sim_export.json with a fresh simulation, then load it here. Until then this shows a bundled sample run so the tab isn't empty.

What's real here, and what isn't: the RMSE/R²/ACT/SLA numbers are genuinely computed by numpy and a discrete-event queueing simulation in edge_ndt_digital_twin_sim.py, averaged over multiple independently-seeded runs (not hand-tuned JS, not a single lucky seed). What's not real is the underlying model: the twin's prediction error is a hand-tuned regression-to-mean + noise process, not a forward pass of digital_twin/model.py's trained GNN, because Phase 2/5 of the project checklist aren't complete yet. Swap in digital_twin/saved_models/eval_results/fidelity_summary.csv once those land — the loader here accepts any JSON matching the same schema.
